## 1. Product Overview

PeerLink is a **privacy-first, local-first personal data mesh** designed to synchronize folders, stream multi-gigabyte files, and share device capabilities seamlessly across personal devices without relying on third-party cloud storage or unencrypted third-party relays. 

All operations prioritize **user data sovereignty**: files are transferred directly between peer nodes over local high-speed connections (QUIC/TLS), protected by end-to-end cryptographic keys stored exclusively on your devices.

---

## 2. What's New in PeerLink 1.0.0

### 2.1 Cryptographic Identity & Trust Circles
* **Zero-Knowledge Device Identity**: Each node generates an Ed25519 key pair stored in the OS secure keystore (Windows DPAPI, macOS Keychain, Linux Keyring, Android Keystore).
* **Trust-on-First-Use (TOFU) & QR Code Pairing**: Safe pairing using high-contrast QR codes, out-of-band numeric SAS codes, and zero-leak discovery tokens.
* **Instant Device Revocation**: Single-click device revocation immediately severs active sessions, purges shared session keys, and permanently blacklists compromised nodes.

### 2.2 Multi-Transport Peer Networking
* **High-Throughput Direct QUIC**: Hardware-accelerated UDP datagram transport with stream multiplexing and connection migration for high-bandwidth Wi-Fi and 5G.
* **Direct TCP with TLS 1.3**: Fallback transport with modern AEAD cipher suites (`TLS_AES_128_GCM_SHA256`, `TLS_CHACHA20_POLY1305_SHA256`).
* **Authenticated coturn STUN/TURN Relays**: Seamless fallback for strict symmetric NATs and enterprise corporate firewalls. Relays observe only opaque end-to-end ciphertext.
* **Local Subnet Auto-Discovery**: Low-overhead mDNS and DNS-SD discovery with randomized jitter to eliminate multicast storms.

### 2.3 Resilient File Transfer Engine
* **Chunk-Based Streaming Architecture**: Large files are divided into deterministic 1 MB chunks verified by SHA-256 integrity hashes.
* **Non-Destructive Checkpointing**: Active transfers automatically pause on network loss or application dismissal and resume without restarting.
* **Adaptive Bandwidth Management**: Configurable bandwidth throttling and prioritization queues.
* **Automated Staging & Safety**: Incomplete transfers are staged in isolated quarantine paths until fully reassembled and verified.

### 2.4 Causal CRDT Folder Synchronization
* **Vector Clock Causal Versioning**: Accurate conflict detection using Lamport causality; concurrent edits are preserved without silent data loss.
* **Mass-Change Safety Protector**: Halts sync automatically if anomalous bulk deletions (> 5 files or > 50% repository) occur, protecting against ransomware or accidental deletion.
* **Selective Sync & Git-Ignore Rules**: Granular directory exclusion rules and pattern matching.

### 2.5 Encrypted Clipboard Synchronization
* **Peer Clipboard Bridge**: Synchronizes text snippets and images across paired devices in real time.
* **Security Sanitization**: Automatically filters out recognized password patterns, credit card formats, and transient tokens before transmission.

### 2.6 Cloud Control Plane (Optional Supabase Integration)
* **Presence & Signaling Directory**: Enables peer discovery across separate networks and mobile cellular connections.
* **Zero-Trust Client Invariant**: Client applications strictly use public anon tokens; no service-role secrets are ever distributed or accepted.
* **Full Offline Autonomy**: If the cloud control plane is unreachable, all local features (LAN sync, direct transfers, clipboard) operate 100% unimpaired.

## 6. Known Limitations & Operational Guidance

Detailed platform-specific workarounds and network edge cases are documented in [`docs/beta/KNOWN-ISSUES.md`](file:///c:/Users/WIN_10/.gemini/antigravity/scratch/New%20folder/PeerLink/docs/beta/KNOWN-ISSUES.md):
* **Android Battery Optimization**: Certain OEM Android skins (Samsung OneUI, Xiaomi MIUI) require setting battery usage to "Unrestricted" for continuous background sync.
* **Windows MAX_PATH**: Extremely deep file paths (> 260 characters) require the standard Windows Win32 Long Paths registry flag enabled.
* **macOS Local Network Permissions**: macOS 15 Sequoia requires granting the Local Network permission dialog on initial launch for mDNS discovery.
